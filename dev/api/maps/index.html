MultilevelKernelInterpolation.DefaultI2IStrategy — Type
DefaultI2IStrategy()

Store each I2I transfer as one tensor-product matrix with the DenseI2I trait. For N nodes per axis in D dimensions, a dense matrix needs O(N^(2D)) storage. B-spline matrices can stay sparse because their basis functions have compact support.

MultilevelKernelInterpolation.DenseI2OStrategy — Type
DenseI2OStrategy(; symmetryreduced=false)

Use dense I2OTranslationCollection couplings.

With symmetryreduced=true, store one matrix for each group of lattice directions related by symmetry. Other directions reuse it through grid permutations, without an extra approximation. In 3-D, these permutations have O(b^3) entries versus O(b^6) for a dense coupling.

Reduction supports Galerkin maps with non-B-spline polynomials and scalar or supported 3-by-3 kernels (efie, MWHyperSingular3D, MWDoubleLayer3D). Unsupported combinations error; non-lattice trees use unreduced couplings. Reduction is off by default.

MultilevelKernelInterpolation.GalerkinCore — Type
GalerkinCore(operator, space; kwargs...)
GalerkinCore(operator, space, tree; kwargs...)

Build the read-only data for a Galerkin map: tree, plans, near interactions, moment collections, and translations. The core also stores metadata for workspace allocation.

Use H2Workspace(core, scheduling) to get an executable LinearMap:

core = GalerkinCore(operator, space)
ws = H2Workspace(core, scheduling)
mul!(y, ws, x)

For concurrent multiplications, give each task its own workspace over the same core. GalerkinMap builds a core and one workspace in a single call.

MultilevelKernelInterpolation.InterpolationStrategy — Type
InterpolationStrategy(operator, testspace, trialspace=testspace; polynomialstrategy, momentassemblystrategy, nearinteractionsstrategy, nearfieldstrategy, translatorstrategy, scheduler)

Configure construction and scheduling for GalerkinMap or PetrovGalerkinMap. Pass one space for Galerkin, or both test and trial spaces for Petrov-Galerkin. The spaces determine the default near-interaction quadrature through BEAST.defaultquadstrat.

Defaults to order-6 equidistant Lagrange polynomials and FFT-accelerated Toeplitz I2O. These differ from the standalone PolynomialStrategy and TranslatorStrategy defaults (Chebyshev and dense I2O). Toeplitz requires an equidistant grid, so keep the polynomial and I2O choices compatible when overriding either.

MultilevelKernelInterpolation.OneDimI2IStrategy — Type
OneDimI2IStrategy()

Store one matrix per axis with the SeparableI2I trait and apply them successively. Storage is O(D*N^2) for N nodes per axis, rather than O(N^(2D)) for a combined dense matrix. This saves memory at high Lagrange orders, but uses more, smaller operations. DefaultO2OStrategy builds the matching O2O cache automatically.

MultilevelKernelInterpolation.ToeplitzI2OStrategy — Type
ToeplitzI2OStrategy(; symmetryreduced=false)

Use FFT-accelerated ToeplitzI2OTranslationCollection couplings.

With symmetryreduced=true, directions related by lattice symmetry share one difference tensor through index permutations. This adds no approximation. Reduction is off by default; non-lattice displacements, such as offset block-tree roots, use unreduced couplings.

MultilevelKernelInterpolation._coreandworkspace — Method
_coreandworkspace(Core, args; scheduling=nothing, checkaliasing=false, kwargs...)

Build a core and one workspace for GalerkinMap or PetrovGalerkinMap. scheduling and checkaliasing apply to the workspace; other keywords go to the core.

With scheduling=nothing, use the core's default scheduler on its levels, serial inner kernels, and one chunk per thread. checkaliasing=true runs the optional O(n^2) pooled-moment check after workspace allocation; see assertmomentaliasing.

Check a map's pooled moments with H2Factory.checkmomentaliasing. Return A if no error-severity findings exist; otherwise throw with the findings.

MultilevelKernelInterpolation.checkprotrusionsafety — Method
checkprotrusionsafety(receivingtree, receivingpolynomials, translatingtree, translatingpolynomials, plan)

Check I2O sampling boxes on separate receiving and translating trees. Each side uses its own polynomial extension, which can differ with the function space. The warning margin is the smaller of the two raw box half-sizes.

source
MultilevelKernelInterpolation.checkprotrusionsafety — Method
checkprotrusionsafety(tree, treepolynomials, plan)

Check the extended sampling boxes for every I2O pair in plan. Throw if two boxes overlap or touch: evaluating the kernel there can produce singular couplings or a native crash. Warn when the gap is positive but smaller than the lesser raw box half-size, the empirical margin in arXiv:2606.13482, Section VI-B.

Uses each node's actual center, half-size, and realized polynomial extension, without assuming uniform tree geometry or a particular near/far criterion. This form uses one tree and polynomial family for both sides.
